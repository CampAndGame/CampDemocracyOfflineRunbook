# Диагностика WS/таймера на стенде Democracy — установка

Один статичный файл `diag.html`, отдаётся nginx'ом по адресу `/diag`.
Ничего не пересобирается, контейнеры приложения не трогаются.

## Установка (в свой docker-compose)

1. Положить `diag.html` рядом со своим `docker-compose.yml`.

2. В сервис **nginx** добавить volume:

```yaml
    volumes:
      - ./diag.html:/etc/nginx/diag.html:ro
```

3. В конфиг nginx (в server-блок, рядом с остальными location) добавить:

```nginx
    location = /diag {
        default_type text/html;
        alias /etc/nginx/diag.html;
    }
```

4. Пересоздать nginx-контейнер:

```bash
docker compose up -d nginx
```

Нюанс: если потом править `diag.html` на месте — нужен `docker restart`
nginx-контейнера, single-file bind-mount не подхватывает замену файла на лету.
Браузер страницу тоже кэширует — обновлять с Cmd/Ctrl+Shift+R.

## Использование

Открыть `http://<стенд>/diag`, ввести пароль админки, «Войти и проверить».

Четыре вердикта сверху:

- **WebSocket-транспорт** — страница подключается к `/api/democracy/ws/websocket`
  честным WebSocket'ом. Красный вердикт = апгрейд не проходит, значит и админка
  сидит на SockJS-fallback (xhr-polling) — события будут приходить пачками с
  задержкой в секунды. Смотреть проксирование WS в nginx.
- **REST-задержка** — 10 запросов к API, медиана/max. Медиана > 500мс = тормозит
  железо/БД стенда.
- **Троттлинг вкладки** — дрейф локального таймера браузера. Красный = вкладка
  уходит в фон и браузер троттлит её таймеры и звук. Это же происходит с
  вкладкой админки! Держать админку активной вкладкой в отдельном окне.
- **Ровность тиков** — интервалы между WS-событиями таймера (норма ~1000мс).
  p95 > 1300мс = тики с сервера идут рвано (GC/CPU стенда).

Ниже — live-лог: страница подписана на все топики выбранной игры
(controls, sound, pre-start, team/*) и пишет каждое событие с точным временем
и Δ. Можно держать открытой во время реальной игры: ведущий жмёт кнопки в
админке — в логе видно, когда события реально ушли с сервера. Если здесь
события приходят вовремя, а в админке звук/таймер запаздывает — проблема в
браузере/вкладке админки, не в сервере.

Кнопка **«Тест "показать вопрос"»** — активный замер полного цикла:
REST-команда → SOUND → тики пре-старта → старт времени команды, с авто-скрытием
вопроса через 5 секунд. Внимание: съедает ~5 секунд времени активной команды,
на живой игре не жать.

## Как читать типовые случаи

| Симптом | Куда смотреть |
|---|---|
| всё зелёное, но в админке звук/таймер запаздывает | троттлинг вкладки админки (фон), держать активной |
| транспорт красный | nginx: локация WS без `Upgrade`/`Connection` заголовков |
| тики рвано (p95 > 1300мс) | `docker stats` на стенде, CPU/память api-контейнера |
| REST сотни мс | железо/диск стенда, логи api |
| задержка 0–1с «то есть, то нет» | норма: серверный тикер раз в секунду, клик попадает в случайную фазу |
